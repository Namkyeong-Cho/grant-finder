# Grant Finder

교수·연구자를 위한 연구지원 탐색 실습입니다. CV 파일 또는 연구자 홈페이지에서 조건을 읽고, 알고 있는 사업·사이트를 더해 공통 후보군과 웹에서 추가 기회를 찾습니다. **공고 / 예정일 / 현재 단계 / 다음 할 일**을 한 화면에서 확인합니다. 모델 분석에는 Ollama를 사용합니다.

CV 업로드 → 본문 추출·JSON 저장 → 후보 탐색 → 지원 준비 순서로 사용하는 실습입니다. 아래에서 설치와 실행 방법을 확인할 수 있습니다.

## Qwen3.8 27B 모델 준비

**Qwen**은 Alibaba Qwen 팀이 개발한 모델 계열이고, **Ollama**는 모델 다운로드·실행과 로컬 API 제공을 맡습니다. 이 강의에서는 **`qwen3.8:27b`**를 사용합니다. [Qwen 공식 개요](https://qwen.readthedocs.io/en/stable/getting_started/concepts.html) · [모델 배포 페이지](https://ollama.com/library/qwen3.8:27b)

1. [Ollama 다운로드](https://ollama.com/download)에서 운영체제에 맞게 설치합니다. macOS·Windows에서는 설치한 Ollama 앱을 실행하고 터미널을 새로 엽니다.
2. Linux는 [공식 설치 안내](https://docs.ollama.com/linux)를 따릅니다. 수동 실행이 필요하면 별도 터미널에서 `ollama serve`를 실행해 유지합니다.
3. 다음 명령으로 모델을 다운로드하고 첫 응답을 확인합니다.

```bash
ollama -v
ollama pull qwen3.8:27b
ollama list
ollama show qwen3.8:27b
ollama run qwen3.8:27b
```

대화에서 “연구비 지원사업 탐색의 목적을 한국어 두 문장으로 설명해 주세요.”를 입력합니다. 응답을 확인한 뒤 대화 안에 `/bye`를 입력해 종료합니다. Ollama 서비스는 다음 프로그램 연결을 위해 계속 실행합니다. [CLI 명령](https://docs.ollama.com/cli) · [대화 명령](https://github.com/ollama/ollama/blob/main/cmd/interactive.go)

2026-11-08 공식 배포 페이지 기준 다운로드 크기는 약 **18GB**입니다. 실행할 때는 가중치 외에도 문맥 캐시와 추론 작업 공간이 메모리를 사용합니다. 로컬 추론에는 외부 LLM API 키가 필요 없으며, 모델 다운로드와 공고 웹 검색에는 인터넷을 사용합니다. [로컬 API](https://docs.ollama.com/api/introduction) · [메모리·문맥 FAQ](https://docs.ollama.com/faq)

## 탐색 화면 실행

Python 3.10 이상을 설치한 뒤, 배포받은 **`grant_finder` 폴더**를 터미널에서 엽니다. `run.py`와 `requirements-search.txt`가 보이는 위치에서 실행합니다. 상위 폴더 이름이나 저장 위치는 자유롭게 정할 수 있습니다.

macOS·Linux에서 처음 실행할 때:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-search.txt -r requirements-pdf.txt
python run.py doctor --model qwen3.8:27b
python run.py serve --open --model qwen3.8:27b
```

Windows PowerShell에서 처음 실행할 때:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-search.txt -r requirements-pdf.txt tzdata
.venv\Scripts\python.exe run.py doctor --model qwen3.8:27b
.venv\Scripts\python.exe run.py serve --open --model qwen3.8:27b
```

Windows 명령의 `tzdata`는 마감 계산에 사용하는 IANA 시간대 자료를 제공합니다. [Python 시간대 자료 안내](https://docs.python.org/3/library/zoneinfo.html#data-sources)

이후 macOS·Linux에서는 `source .venv/bin/activate` 후 **`python run.py serve --open --model qwen3.8:27b`**, Windows에서는 **`.venv\Scripts\python.exe run.py serve --open --model qwen3.8:27b`**으로 실행합니다.

`doctor`의 `selected_model`과 `installed_models`에서 `qwen3.8:27b`를 확인합니다. `doctor`는 모델 응답을 생성하지 않고 연결·설치 상태를 점검합니다. 이어서 `serve`가 브라우저에서 `http://127.0.0.1:8765`를 엽니다.

화면은 다음 네 탭으로 구성됩니다.

1. **연구자 정보**: CV 파일을 선택하거나 홈페이지 주소를 등록한 뒤 **분석하고 요약 JSON 만들기**를 누릅니다. 같은 카드에서 요약 JSON을 확인·수정·저장하고, 자료명·정보 요약·정리 위치·파일 열기·비우기를 관리합니다. JSON은 기본으로 펼쳐지며 저장된 연구자가 없으면 빈 JSON 형식을 표시합니다.
2. **탐색 대상 선정**: 연구자 정보가 없어도 보유 사업·사이트를 선택하고 저장할 수 있습니다. 이 목록은 별도 초안으로 보관합니다. 연구자 정보를 저장한 경우에는 맞춤 추천도 준비하며, 추천과 전체 목록을 오가거나 직접 아는 곳을 추가할 수 있습니다. 필요하면 기존 목록 아래의 추가 탐색 영역에서 공개 웹 검색을 실행합니다.
3. **지원 후보**: 선택한 보유 사업과 사이트, 연구 정보 기반 웹 검색으로 후보를 찾습니다. 원문·자격·일정을 검토하고 지원할 항목을 고릅니다.
4. **마감 전 지원**: 선택한 전형 중 **마감 전으로 확인된 항목**을 기본으로 표시합니다. 마감 미확인과 마감 지난 기록은 별도 보기로 확인합니다. 접수·마감·공고 예정월이 현재보다 달력상 2개월 이상 뒤라면 정확한 마감일이 없어도 마감 전에 포함하고 **접수 예정·마감 예정·공고 예정**으로 구분합니다. 월 범위는 시작 월을 기준으로 판단하며, 결과 발표·연구 시작·과거 공모 이력은 이 분류에 사용하지 않습니다. 한 사업에 여러 전형이 있으면 현재 보기의 마감 상태에 해당하는 전형만 표시하며, 저장된 계획은 유지합니다.

3번 **지원 후보**에서는 사업명 앞 체크박스로 해당 사업의 전형 전체를 선택하고, 사업을 펼쳐 전형별로 선택할 수 있습니다. **목록 전체 선택**은 현재 검색·필터에 맞는 후보 전체에 적용하며, 아직 펼쳐 보지 않은 항목도 포함합니다. 선택 개수를 확인하고 **선택 항목 지원 목록에 추가**를 누르면 4번에서 준비할 항목으로 저장합니다. 이미 추가한 전형은 중복 저장하지 않으며, 일부 저장이 실패하면 남은 선택을 유지합니다.

보유 목록에는 현재 분류의 **모두 선택·모두 해제**, 검색 중인 **검색 결과 모두 선택·해제**, 두 분류를 합친 **사업·사이트 모두 선택**이 있습니다. **추천만 보기**와 **선택한 항목만**으로 표시 범위를 바꿀 수 있습니다. 목록 밖 항목은 **목록에 없는 사업·사이트 직접 추가**에서 유형·이름·주소·메모를 입력하고 **선택 목록 저장**을 누릅니다. 연구자 정보가 있으면 해당 작업공간에, 없으면 선택 초안에 저장합니다.

기본으로 접힌 **키워드·정보로 추가 탐색**을 열고 키워드나 조건을 1~1,000자로 입력한 뒤 **지원사업·사이트 찾기**를 누르면 여러 검색어로 공개 웹을 검색합니다. 연구자 정보 없이도 사용할 수 있습니다. **연구자 정보 가져오기**는 저장된 연구 요약·키워드를 입력란에 채우며, 즉시 검색하지 않습니다.

결과에는 실제 검색어·검색 상태와 제목·주소·검색 요약·확인 시각을 표시합니다. 결과의 종류를 지원사업 또는 기관·사이트로 고르고 **선택 목록에 추가**한 뒤 기존 **선택 목록 저장**으로 저장합니다. 검색만 실행해서 기존 선택 목록이나 3번의 지원 후보가 바뀌지는 않습니다. 지원조건과 마감은 연결된 공고 원문에서 확인합니다.

연구자 없이 저장한 탐색 대상은 `state/selection_draft.json`에 보관합니다. 연구자 정보가 없는 상태에서 새 연구자를 처음 저장하면 이 초안을 연결합니다. 이미 저장된 연구자를 다시 열 때는 그 연구자의 기존 선택과 별도 초안을 유지합니다. 맞춤 추천을 준비하는 중이거나 추천이 없거나 실패한 경우에도 보유 목록을 표시합니다.

**이름·연구 분야·CV 등록은 검색의 필수 조건이 아닙니다.** 분석 결과에 없는 정보는 `null`·빈 목록으로 유지하며, 빈 요약 JSON도 저장할 수 있습니다. 연구 분야나 직접 작성한 조건이 있으면 해당 내용을 맞춤 탐색에 반영합니다. 둘 다 없으면 선택한 사업·사이트로 탐색하며, 출발점도 없으면 일반 연구지원 공고를 검색합니다. 연구자 정보가 없는 상태에서 탐색 버튼을 누르면 현재 JSON과 선택 목록을 저장한 뒤 실행하며, 처음 화면을 열거나 탭을 이동하는 것만으로 저장하지는 않습니다.

빈 JSON의 초기 표시만으로 연구자 정보를 저장하지는 않습니다. 파일 선택·주소 등록만으로는 모델을 호출하지 않으며, 분석 버튼을 눌러야 분석을 시작합니다. JSON을 직접 수정해 저장할 때는 모델을 다시 호출하지 않습니다. 원본 CV 파일은 따로 보관하지 않고, 추출한 연구자 정보와 원래 파일명을 `state/workspaces/cv_<식별자>.json`에 저장합니다. 정리 위치에는 실제 파일의 전체 경로를 표시하며, **파일 열기**로 저장된 JSON 원문을 새 탭에서 볼 수 있습니다.

**비우기**는 현재 연구자의 분석 정보·선택 목록·탐색 결과·지원 계획이 든 작업공간 파일과 해당 작업 기록을 삭제합니다. 저장된 연구자가 있으면 삭제 범위를 확인하며, 탐색 중에는 실행할 수 없습니다. 연구자가 없는 상태에서는 선택 초안을 비웁니다. 다른 연구자의 파일과 공통 목록은 유지합니다. **선택한 곳으로 지원 후보 찾기**는 탐색 한 번을 시작하며, 정기 갱신은 3번의 **자동 탐색 켜기**로 별도 설정합니다.

시작한 탐색은 브라우저 탭을 닫아도 로컬 서버에서 계속 진행합니다. 자동 탐색을 켰을 때 기본 갱신 주기는 24시간이며, 서버가 꺼져 있던 동안 지난 갱신은 다음 실행 때 다시 시작합니다. 모델 추론에는 로컬 Ollama만 사용합니다. 같은 연구 조건·사업 자료·모델로 만든 분류와 검색어는 재사용하며, 웹 결과는 갱신 주기에 맞춰 다시 조회합니다. 선택한 지원사업은 다음 원문 검토에서 먼저 확인합니다.

저장 파일이 없으면 프로필과 선택 목록이 비어 있습니다. CV 파일·홈페이지별로 `state/workspaces/`에 조건·선택 목록·발견한 사업과 사이트·탐색 이력·지원 계획을 저장합니다. 새로 탐색해도 이전에 발견한 정보와 작성 중인 지원 계획은 남습니다. 탐색이 실패하면 마지막 성공 결과를 유지합니다. 공통 후보의 사업명·기관·지원 방식·자격 안내는 `data/public_opportunities.json`, 등록 URL은 `data/sources.json`에서 읽습니다. 작업 진행 상태는 `state/jobs/`에 따로 저장합니다.

웹 검색 패키지는 [DDGS](https://github.com/deedy5/ddgs)를 사용합니다. 일반 웹 검색엔진을 `duckduckgo → brave → yahoo` 순서로 시도하고, 한국어 검색에는 `kr-ko`, 나머지에는 `us-en` 지역 코드를 사용합니다. 검색에 실패하면 화면에는 조회 상태만 간단히 표시하며, 상세 오류와 검색엔진별 시도 기록은 저장된 진단 정보에 남깁니다. 검색 결과에는 제목·주소·검색 요약과 확인 시각을 남깁니다. 지원자격과 세부 일정은 연결된 공고 원문에서 확인합니다.

## 학교 공고와 하이브레인넷

기관·사이트에서 **하이브레인넷 연구지원 정보**를 선택하면 공개 검색 결과를 탐색에 포함합니다. 하이브레인넷은 직접 자동수집이 제한되어 있어 검색 요약을 지원자격·마감의 확인 근거로 쓰지 않습니다. 원문은 직접 확인합니다.

학교 포털·연구처·산학협력단은 **목록에 없는 사업·사이트 직접 추가**에서 입력 유형을 기관·사이트로 고르고 공고 목록 주소를 등록합니다. 선택 목록을 저장한 뒤 탐색하면 공개 공고 링크를 직접 읽어 기존 후보와 합칩니다. 등록 사이트와 직접 입력한 사이트 모두 사이트 지정 웹 검색에도 사용합니다. 로그인 페이지는 수집 오류로 표시하며 로그인 세션을 자동으로 가져오지 않습니다.

직접 목록 수집은 한 번에 최대 12곳·사이트당 20건·전체 120건으로 제한하며, 정상 수집 결과는 24시간 동안 재사용합니다. 목록에서 찾은 공고는 검토 순서에서 우선하며 기존 원문 검토 범위(최대 24개 사업·원문 8개)는 유지합니다. 수집·검색 상태와 공고 출처는 작업공간에 저장합니다.

## 공개 연구지원 조사 자료

공개 공고를 바탕으로 **82개 지원사업 안의 96개 세부 전형**을 정리했습니다. 전형 기준으로 정부 25개, 기업·민간재단 35개, 국제협력·수학 방문연구 36개입니다. 현재 모집·수시·공식 예정·다음 회차·모집 미확인을 구분하며, 연구비·방문체류·계산자원을 필터로 나눌 수 있습니다. 수학·AI 전문 경로인 AI for Math Seed·Annual, AI2050 비공개 추천, 과학 오픈소스 공동개발도 포함합니다. 이 목록은 특정 연구자의 신청자격을 확인한 결과가 아닙니다.

**같은 사업은 한 항목으로 표시하고 펼치면 전형·회차별 자격과 마감을 비교합니다.** 삼성 Science·Technology, Amazon ARA의 3개 공모, AI for Math Seed·Annual 등이 묶입니다. 상세 추적 6건도 정부·삼성·Amazon·포스코의 4개 사업 안에 배치합니다. 묶음 규칙은 `data/program_groups.json`에서 관리하며 개별 전형의 ID·지원 이력·자격·마감·남은 시간은 각각 유지합니다.

```bash
python3 run.py personalize --profile data/profile.local.json --open
```

이 명령은 `data/research/*_candidates.json`의 공식자료 조사와 직접 작성한 프로필을 병합합니다. 먼저 아래 **4. 내 프로필로 비교**를 따라 `data/profile.local.json`에 본인 자료를 입력합니다. `personalize`는 `is_demo: true`인 가상 프로필을 받지 않습니다.

배포본의 기본 프로필은 **`data/profile.example.json`의 수업용 가상 자료**입니다. 개인 CV·확인사항·신청 이력과 이전 실행 결과는 포함하지 않습니다. 본인 자료를 입력한 뒤에는 원문 요강과 경력·수행 과제를 대조해야 합니다.

확장 후보는 **2026년 11월 6~7일에 확인한 공식자료 조사 결과**입니다. 각 항목에 확인일을 표시합니다. 기존의 자동 본문 수집 4곳·상세 추적 6건과 구분합니다. `personalize` 실행 후에는 지정한 프로필을 `run`의 기본값으로 저장하며, `demo`는 가상 프로필을 사용합니다. 질문 도구도 현재 프로필에 맞는 확장 후보를 검색·조회합니다.

## 연구지원 사이트 메모리

**사이트와 페이지 주소는 `data/sources.json` 한 곳에서 관리합니다.** 사이트 관리항목 77개와 중복을 제거한 페이지·첨부 165개를 모았습니다. 사이트 항목에는 URL 미입력 상태인 소속 대학 항목도 포함됩니다.

- `sources`: 사이트 ID·이름·허용 도메인·수집 설정을 저장합니다. `enabled`는 CLI `discover`의 설정형 수집기 사용 여부이며, 웹 화면에서 선택한 공개 사이트의 목록 수집은 별도로 동작합니다.
- `pages`: 공고·신청·목록·첨부별 `id`, `source_id`, `title`, `url`, `checked_on`을 저장합니다. **주소가 바뀌면 여기의 `url`을 수정합니다.**
- 후보·상세 추적 씨드·모집 시기 자료는 `source_ref`, `additional_source_refs`로 페이지 ID를 참조합니다. 같은 페이지를 쓰는 여러 지원사업도 각각 유지합니다.
- 실행 후 `outputs`, `cache`에 저장되는 URL은 해당 실행의 수집·판정 기록입니다. 현재 사이트 설정은 이 JSON을 사용합니다.

사이트 목록을 보거나 검색하려면 다음을 실행합니다. 웹 조회와 모델 호출은 없습니다.

```bash
python3 run.py sources
python3 run.py sources --query samsung
python3 run.py sources --json
```

공통 목록에 사이트를 추가할 때는 `sources`에 ID와 설정을, `pages`에 실제 확인한 페이지를 등록한 후 후보에서 해당 ID를 참조합니다. CLI 목록 수집에 사용할 출처는 수집기 설정을 확인한 뒤 `enabled`를 켭니다. 수정한 주소를 반영해 개인화 보고서를 만들려면 본인 프로필을 작성한 뒤 `python3 run.py personalize --profile data/profile.local.json --open`을 실행합니다.

## 사람이 입력하는 지원 이력

지원 이력 파일은 배포본에 포함하지 않습니다. 필요할 때 `data/application_history.json`을 `{"entries": []}` 내용으로 만들고 직접 수정합니다. 파일이 없으면 빈 이력으로 처리합니다.

1. `entries` 배열에 기록 객체를 추가합니다. 고유한 `id`, 본인 프로필의 `id`와 같은 `profile_id`, 사업명인 `program`을 입력합니다.
2. 연도/회차는 `round`, 지원일은 `submitted_on`, 결과 확인일은 `decided_on`, 메모는 `notes`에 입력합니다. 날짜는 `YYYY-MM-DD` 또는 `null`입니다. 상태 `status`에는 `preparing`, `submitted`, `selected`, `rejected`, `unknown` 등을 사용합니다. 전체 상태는 `grantfinder/application_history.py`의 `STATUSES`와 `grantfinder/report.py`의 `PROGRESS`에 정의되어 있습니다.
3. `python3 run.py report --open`을 실행하면 HTML·Markdown의 **지원 이력**에 반영됩니다. 웹 조회나 모델 호출은 없습니다.

현재 프로필 ID와 일치하는 기록만 표시합니다. 같은 사업에 다시 지원하면 이전 기록을 남기고 새 회차를 추가합니다. 이 파일은 프로그램이 덮어쓰지 않습니다. 선정·미선정은 사람이 입력하며, 현재 수행 과제나 자격 판정은 프로필에서 별도로 관리합니다.

## 1. 실행 위치와 준비

배포받은 `grant_finder` 폴더에서 앞의 환경 준비를 마친 뒤 실행합니다.

```bash
python run.py doctor --model qwen3.8:27b
```

Windows PowerShell에서는 `.venv\Scripts\python.exe run.py doctor --model qwen3.8:27b`를 사용합니다.

확인할 항목은 Python 환경, Ollama 연결, 설치된 모델입니다. 강의에서는 `qwen3.8:27b`로 통일합니다. 기본 실행에는 Python 3.10 이상과 표준 라이브러리를 사용합니다. PDF 처리를 추가할 때만 `python3 -m pip install -r requirements-pdf.txt`를 실행합니다.

Ollama 서버는 같은 PC에서 실행합니다. 코드의 `127.0.0.1`은 코드를 실행하는 컴퓨터를 가리킵니다. 외부 LLM API 키는 사용하지 않습니다.

## 2. 먼저 보고서 형식 확인

아래의 `report`·`demo`·`run`은 `outputs/`를 사용하는 CLI 보고서 흐름입니다. 웹 탐색 화면의 연구자별 데이터는 `state/workspaces/`에서 별도로 관리합니다. 배포본에는 이전 실행 결과가 없으므로 수업용 가상 데이터로 먼저 보고서를 만듭니다.

```bash
python3 run.py demo --as-of 2026-11-06
```

이 명령은 **수업용 가상 교수 프로필**과 실제 공식 공고를 미리 검토한 데이터를 사용합니다. 이번 실행에서 웹을 재조회하거나 Ollama 추론을 실행한 결과는 아닙니다. 보고서에서 다음을 확인합니다.

- 정부 과제의 연구자 마감과 기관승인 마감이 구분되는지.
- 공식 예정월·과거 모집 이력이 확정 마감과 구분되는지.
- 개인 경력이 비어 있으면 `확인 필요`로 남는지.
- `이번에 할 일`과 각 판단의 공식 출처를 볼 수 있는지.

`demo`와 `run`은 `outputs/latest_report.html`과 `outputs/latest_report.md`를 함께 생성합니다. `--as-of`는 수업용 기준일을 고정하는 옵션입니다. 평소 실행에서는 생략하면 현재 한국시간을 사용합니다.

생성한 분석 결과를 HTML로 다시 열려면 다음을 실행합니다.

```bash
python3 run.py report --open
```

`report`는 기존 분석 결과로 HTML과 Markdown을 다시 생성합니다. 웹 수집이나 LLM 추론을 호출하지 않으며, 기존 보고서의 판정시각을 유지합니다. 새로운 기준시각으로 다시 판정하려면 `demo` 또는 `run`의 `--as-of`를 사용합니다.

기본 결과 파일은 **`outputs/latest_report.html`**입니다. 생성 후 파일을 더블클릭해도 브라우저에서 열립니다. HTML 안에 스타일과 검색·필터 기능이 들어 있으므로 웹서버, 호스팅, 외부 JavaScript 설치가 필요하지 않습니다.

HTML에서는 공고명·키워드 검색, 접수상태·기관 필터, 공고별 상세 근거, 일정과 미완료 할 일을 확인합니다. 후보 목록·우선 카드·상세 공고·일정표에는 마감까지 남은 시간을 표시합니다. 브라우저의 현재 시각 기준으로 1분마다 갱신되며 7일 이내는 주황색, 24시간 이내는 빨간색입니다. 날짜만 있는 마감은 원래 지역 기준 `D-n · 시각 미기재`로 표시하고, 미확정·상시 모집에는 시각을 만들지 않습니다. 읽기 전용 보고서이며, 실제 진행 상태는 아래의 CLI 명령으로 기록합니다.

## 3. 로컬 모델로 실제 분석

```bash
python3 run.py run --model qwen3.8:27b --limit 2 --as-of 2026-11-06
```

저장된 공식 공고 원문을 모델이 읽고 JSON으로 추출합니다. 이후 코드가 날짜·형식을 검사하고 자격 비교·보고서를 만듭니다. 처음에는 공고 수를 적게 지정해 모델의 출력과 원문을 대조합니다.

로컬 모델은 접수 시작과 마감 같은 일정 종류를 혼동할 수 있습니다. 추출값은 원문 인용·날짜 검증과 준비된 검토 정답표 대조를 거치며, 불일치는 `확인 필요`로 남깁니다. 모델의 원출력도 추출 메타데이터에 보존합니다.

같은 원문·모델의 분석 결과가 있으면 추출 캐시를 재사용합니다. 다시 추론할 때는 `--reanalyze`를 붙입니다. 콘솔의 `로컬 모델 분석`과 `분석 캐시` 표시를 구분합니다.

최신 웹 원문을 수집한 뒤 분석하려면 다음과 같이 실행합니다.

```bash
python3 run.py run --live --model qwen3.8:27b --limit 2
```

웹 수집 실패와 LLM 분석 실패는 실행 결과에 따로 표시됩니다. 저장한 예전 원문을 최신 공고 확인 결과로 표시하지 않습니다.

모델명을 매번 입력하지 않으려면 환경변수로 지정할 수 있습니다.

```bash
export OLLAMA_MODEL="설치된_모델명"
python3 run.py run --limit 2
```

`OLLAMA_HOST`는 로컬 서버 주소를 설정할 때 사용합니다. 외부 호스트를 통한 LLM 호출은 허용하지 않습니다.

## 4. 내 프로필로 비교

```bash
cp data/profile.example.json data/profile.local.json
python3 run.py run --profile data/profile.local.json --limit 2
```

복사한 파일을 편집합니다. 예시는 **수업용 가상 교수**이며 실제 교수님의 경력·국적·과제 이력이 아닙니다. 본인 자료를 입력했다면 `is_demo`를 `false`로 바꿉니다.

| 항목 | 입력 방식 |
| --- | --- |
| 학위·최초 임용·생년월일 | `YYYY-MM-DD`. 모르면 `null` 유지 |
| 국적 | `KR` 등 코드. 미확인 시 `null` |
| 수행 중 과제 | 모르면 `null`, 없음을 확인했다면 `[]` |
| 서류 보유 여부 | 보유 `true`, 미보유 `false`, 확인 전 `null` |
| 대학 내부마감 | `internal_deadlines`에 공고 ID와 시간대 포함 ISO 날짜 입력 |
| 대학 공지 | `institution_url`에 소속 연구처·산학협력단 주소 입력 |

프로필 정보가 부족하거나 세부요강을 더 읽어야 하는 조건은 `확인 필요`로 출력합니다. 연구주제 일치와 신청자격을 따로 봅니다.

## 저장 파일과 확인 범위

현재 **사이트 관리항목 77개·페이지 및 첨부 URL 165개**를 한 JSON에 등록했습니다. CLI의 고정 공고 분석용으로 **4개 출처의 본문 수집**과 **6개 공고·트랙의 분석**을 준비했습니다. 6개는 정부 핵심·신진 2개, 삼성 상·하반기 2개, Amazon 가을 공모, 포스코 제18기입니다. CLI 목록 수집 대상은 `enabled`로 표시하며, 웹 탐색 화면은 선택한 공개 사이트와 검색 결과를 별도로 수집·검토합니다.

포스코 공고의 핵심 일정·자격은 이미지 포스터에 들어 있습니다. 현재 HTML 원문 수집만으로는 그 내용을 모두 읽지 못하므로 `확인 필요`로 남깁니다. 준비된 검토자료의 포스터 확인 내용과 자동 추출 결과를 구분합니다.

CLI `discover`에서 발견한 링크를 `run`으로 분석하려면 `data/seeds.json`에 공고·트랙을 등록하고 공식 원문 저장본 또는 수집 출처를 연결합니다. 웹 화면의 **지원 후보** 탐색은 별도 씨드 등록 없이 검색·공개 목록에서 찾은 공고를 기존 원문 검토 범위 안에서 검토합니다. 신청서 제출은 자동으로 수행하지 않습니다.

아래 `outputs/`·`state/` 항목은 실행하면서 생성하는 파일이며 배포본에는 포함하지 않습니다.

| 파일·폴더 | 내용 |
| --- | --- |
| `data/sources.json` | 사이트·페이지·첨부 URL의 단일 관리 메모리와 수집 설정 |
| `data/program_groups.json` | 같은 지원사업의 세부 유형·전형·회차를 묶는 표시 규칙 |
| `data/application_history.json` | 필요할 때 직접 만드는 회차별 지원일·결과·메모 파일 |

`ask`에는 도구 호출을 지원하는 모델이 필요합니다. `doctor`의 `capabilities`에 `tools`가 있는지 확인합니다. 새로 추론한 원출력은 `extraction_metadata.raw_output`에 보존합니다. 이 필드가 없는 이전 캐시는 `--reanalyze`로 다시 생성할 수 있습니다.

보고서의 할 일 ID를 완료로 기록하면 로컬 진행 데이터에 저장됩니다. 개인 프로필·진행 상태·출력·캐시·실행 이력은 `.gitignore`에 등록했습니다.

**공식 원문**, **미리 준비한 검토 데이터**, **이번 실행에서 모델이 추출한 데이터**는 구분합니다. 원문에 없는 날짜는 비워 둡니다. 결과 발표 예정일이 지났다는 이유로 선정·미선정을 판단하지 않습니다. 신청서 제출과 메일 발송은 수행하지 않습니다. 정기 탐색은 웹 화면에서 자동 탐색을 켰을 때 로컬 서버가 실행 중인 동안 동작합니다.
